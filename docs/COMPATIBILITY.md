# 工作页面兼容性验收

自动注入成功、自动回归通过和完整实机验收是三种不同的结果。只有同一应用构建、同一适配版本下的 14 项人工检查全部通过，界面才显示“当前版本已实机验收”。

## 固定检查项

每项分别检查浅色、深色模式。换用相应的浅/深色主题，并记录测试的主题和截图。

| 场景 | 必须观察的内容 |
|---|---|
| 长对话与滚动 | 多轮消息、长段落、列表与表格可读；上下滚动正常；固定标题和输入区不会与文字重叠 |
| 代码块与横向滚动 | 正文、注释、语法色可辨认；长代码有横向滚动；复制按钮与代码边界正常 |
| 输入框与按钮 | 输入、选区、焦点、附件与模型控件可辨认；禁用状态正常；不发送测试消息 |
| 分栏与调整宽度 | 打开实际工作侧栏并拖动分隔线；各栏滚动、最小宽度和输入区不互相遮挡 |
| 上下文面板 | 打开真正的上下文详情，检查标题、内容、计数、滚动和关闭按钮；用量图标不算面板 |
| 菜单与浮层 | 打开真实菜单或列表框；等动画结束后检查文字、选中、禁用、滚动和浮层底色 |
| 设置窗口 | 打开真实设置页或独立窗口，检查控件、弹层遮罩和浅深色一致性；无需修改账户或权限 |

没有出现的场景保持“待验收”。自动检测只记录出现情况、布局和颜色信息，不能替代目视判断。

## 在 SkinStudio 中验收

1. 先选应用并应用要检查的主题，确保应用卡片显示“已连接”。
2. 在目标软件打开相应工作页面，再点击 SkinStudio 的“兼容性验收 → 检查当前页面”。检查操作不会重启目标软件。
3. 点击“查看截图”核对抓取的实际页面，选中对应的浅/深色场景，填写备注，再人工确认通过或记录问题。
4. 检查下一场景或另一种模式时重新抓取。浅色截图不能用于深色验收；未应用当前适配版本的皮肤不能记录通过。
5. “查看报告”打开本机的验收记录。截图位于 `logs/compatibility/`，报告在 `compatibility.json`，不会上传到图库或 GitHub。

应用 EXE 与核心渲染包的内容指纹、应用版本、适配版本和检查矩阵版本共同限定验收范围。应用文件更新后，旧记录保留，但不能算作新版本通过；卡片提示“应用已更新，需重新验收”。修改适配后也需要重新验收。版本探测记录单独保存在 `compatibility-versions.json`。

## 自动回归

`tests/work-pages.ps1` 用独立 Chromium 测试四款适配 × 两种模式 × 七种工作场景，共 56 项，覆盖长对话、代码横向溢出、固定输入区、分栏、菜单、设置及模式一致性，并检查 MonkeyCode 代码注释对比。测试页面使用合成内容，结果不写入实机通过记录。

验收存储、失败覆盖旧通过、应用更新失效、适配变更、损坏报告保护，以及验收窗口的抓图回调、模式校验和人工确认流程另有回归测试。
